# Presence Studio · Discord Rich Presence Manager

Приложение на C++17 для Windows 10/11 x64. Нативный интерфейс на русском, подключение к настольному Discord через локальный RPC. Установка, токен пользователя и права администратора не нужны.

## Возможности

- Одновременное изменение названия, details и state.
- Несколько вариантов в каждом текстовом поле: каждый вариант с новой строки, автоматическая смена от 15 секунд. Пустые строки пропускаются; списки разной длины повторяются независимо.
- Большая и малая картинки: ключи Art Assets или публичные HTTPS URL; подписи при наведении.
- Таймер прошедшего времени со смещением в минутах, обратный отсчёт или скрытие времени.
- Импорт и экспорт JSON-профилей, сохранение применённых настроек.
- Переподключение при перезапуске Discord, подтверждение обновлений и вывод ошибок RPC.
- Предпросмотр текста и таймера. Изображения проверяются непосредственно в Discord.
- Тёмный интерфейс с вкладками и векторной отрисовкой Direct2D / DirectWrite. Чёткая типографика при масштабировании Windows и переносе между мониторами (Per-Monitor DPI v2).
- Работа в фоне: крестик и сворачивание убирают окно в трей, сохраняя статус, таймер и автосмену. Собственная иконка в нескольких разрешениях.

## Быстрый старт

1. Скачайте ZIP в [Releases](https://github.com/Frish07/Discord-Status/releases/latest), распакуйте и запустите `DiscordPresenceManager.exe`.
2. Откройте настольный Discord и войдите в аккаунт. В настройках Discord разрешите отображение текущей активности в статусе.
3. В [Discord Developer Portal](https://discord.com/developers/applications) создайте приложение и скопируйте **Application ID**. Это публичный идентификатор; секреты и токены не требуются.
4. Вставьте ID в менеджер, заполните название и тексты. Для смены текста введите несколько вариантов с новой строки.
5. При необходимости загрузите изображения в Rich Presence → Art Assets своего приложения. Вставьте ключ картинки (в нижнем регистре) или публичную HTTPS-ссылку на изображение. Путь к локальному файлу не подходит.
6. Выберите таймер. Для режима «Прошло» минуты означают, сколько времени уже прошло; для обратного отсчёта — длительность от момента запуска/сброса.
7. Нажмите **Применить** и дождитесь «Rich Presence обновлён». Следующие изменения могут ждать до 15 секунд. «Применить» сохраняет точку отсчёта текущего таймера; «Сбросить таймер» запускает его заново.

**Скрыть статус** удаляет активность, оставляя приложение открытым. **Крестик, сворачивание и «Свернуть в трей»** прячут окно, сохраняя подключение, таймер и автосмену в фоне. Нажмите значок Presence Studio в трее, чтобы вернуть окно; если значок не виден, раскройте скрытые значки панели задач. Правый клик по значку открывает меню: открыть, скрыть активность или **Выйти**. Только «Выйти» полностью завершает менеджер и отправляет очистку активности. При повторном запуске EXE уже работающий менеджер возвращается из трея. После полного выхода активность включается кнопкой «Применить».

Вкладки **Статус**, **Изображения** и **Время** позволяют редактировать профиль по частям; «Применить статус» отправляет все поля вместе. Изменения формы сохраняются при применении или экспорте. На небольшом экране доступна вертикальная прокрутка окна.

Одновременно публикуется одна активность с двумя строками текста. Название передаётся через `activity.name`; его отображение зависит от версии клиента Discord. Если переопределение не отображается, измените имя приложения в Developer Portal. Изменения в портале и картинки могут появляться с задержкой. Отображение активности также зависит от настроек приватности Discord.

Настройки хранятся в `%LOCALAPPDATA%\DiscordPresenceManager\settings.json`. Экспорт сохраняет форму; импорт заполняет её и требует нажатия «Применить». Файл содержит только введённые поля присутствия, включая URL картинок; проверяйте его перед передачей другим людям.

## Сборка

### Visual Studio 2022+ и CMake 3.20+

```powershell
cmake -S . -B build -A x64 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

Приложение: `build/Release/DiscordPresenceManager.exe`. MSVC runtime подключается статически.

### MSYS2 / MinGW-w64 UCRT64

Установите компилятор `mingw-w64-ucrt-x86_64-gcc`, затем выполните из PowerShell:

```powershell
./scripts/build.ps1
```

Скрипт собирает автономный `build/DiscordPresenceManager.exe` и запускает тесты модели, IPC и окна. IPC-тест использует отдельный named pipe и не меняет настоящий Discord-статус. Он проверяет handshake, фрагментированные пакеты, публикацию, ping/pong и очистку. Тест модели проверяет ротацию, Unicode, таймеры, профили и ограничения. Тест окна проверяет закрытие в трей, реальную автосмену по таймеру скрытого окна, вкладки, масштабирование шрифта при смене DPI и полный выход. Он также изолирован от настоящего Discord.

Перед пересборкой работающего EXE завершите менеджер через **Выйти** в трее. Чтобы собрать новую версию отдельно от запущенной, используйте `./scripts/build.ps1 -OutputDirectory build/release`.

GitHub Actions проверяет сборку MSVC и создаёт ZIP с SHA-256. На отдельных runner-ах **windows-2022 и windows-2025** дополнительно проверяются и новая сборка, и ZIP из последнего опубликованного релиза:

- Контрольная сумма и состав архива.
- Обычные и отложенные DLL-импорты EXE: разрешены только системные библиотеки Windows. Зависимость от Visual C++ Redistributable, Qt, MinGW DLL или WebView2 останавливает проверку.
- Запуск одного EXE из отдельной папки, в том числе с кириллицей и пробелами. В PATH процесса остаются только папки Windows; исходники, сборочные инструменты и дополнительные DLL рядом с EXE отсутствуют.
- Создание и отзывчивость настоящего окна, отсутствие падения после запуска, загруженные модули только из Windows, сворачивание/восстановление и полный выход.

Эти шаги не устанавливают пакеты. Python используется только для проверки в CI и не нужен пользователю. Сами GitHub-hosted runner-ы содержат предустановленные средства разработки, поэтому дополнительно проверяются импорты и реально загруженные DLL, а не только факт запуска. Отчёты JSON сохраняются в артефактах `portability-windows-*`. Публикация тега `v*` создаёт GitHub Release только после успешных проверок обеих систем.

Для пользователя нужны только Windows 10/11 x64 и настольный Discord. Visual Studio, CMake, Python, Qt и отдельный Visual C++ Redistributable для запуска EXE не требуются.

## Устройство

- `src/main.cpp`: Win32 UI, профили и автосмена.
- `src/design.hpp`: векторная отрисовка, палитра и DirectWrite-типографика.
- `assets/app.manifest`: Per-Monitor DPI v2; `assets/app.ico` — иконки 16–256 px (генератор: `scripts/create-icon.py`).
- `src/presence.hpp`: модель и формирование JSON.
- `src/ipc.hpp`: рабочий поток, named pipes `discord-ipc-0…9`, handshake, очереди, подтверждения, ping/pong и переподключение.

Сетевых запросов в приложении нет: оно обращается к локальному клиенту Discord. Discord самостоятельно получает указанные публичные изображения. При нескольких запущенных клиентах используется первый доступный pipe.

Протокол: [Discord RPC](https://github.com/discord/discord-api-docs/blob/main/developers/topics/rpc.mdx), [Rich Presence RPC](https://github.com/discord/discord-rpc/blob/master/documentation/hard-mode.md), [поля присутствия, изображения, имя и время](https://github.com/discord/discord-api-docs/blob/main/developers/discord-social-sdk/development-guides/setting-rich-presence.mdx). Discord рекомендует Social SDK для новых игровых интеграций; этот небольшой Windows-менеджер реализует локальный RPC напрямую.
